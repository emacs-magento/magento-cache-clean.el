#+title: magento-cache-clean.el
#+author: Piotr Kwiecinski

Emacs integration for [[https://github.com/mage-os/magento-cache-clean][mage-os/magento-cache-clean]], a file watcher based cache cleaner for Magento 2.

* Features

- One-shot cache cleaning via =magento-cache-clean= (compilation buffer)
- Watch mode via =magento-cache-clean-watch= (comint; keys go straight to cache-clean)
- Transient menu via =magento-cache-clean-menu=
- Auto-detection of Magento root directory (=app/etc/env.php=)
- Works on remote projects (TRAMP, e.g. =/docker:=)
- Several Magento instances at once: one output buffer and watcher per root
- Per-project configuration via =.dir-locals.el=
- Propagates =envrc= / =direnv= environment to child processes

* Requirements

- Emacs 30.1+
- [[https://github.com/mage-os/magento-cache-clean][cache-clean]], either installed in the project with composer
  (=vendor/bin/cache-clean.js=) or on =PATH= as =cache-clean= or =cache-clean.js=
- =node=, for the =.js= scripts

* Installation

** use-package with vc

#+begin_src emacs-lisp
(use-package magento-cache-clean
  :vc (:url "https://github.com/emacs-magento/magento-cache-clean.el"
       :rev :newest))
#+end_src

Without =:rev :newest=, use-package installs the commit that last changed
the =Version:= header instead of the latest one.

** Manual

Clone the repository and add it to your =load-path=:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/magento-cache-clean.el")
(require 'magento-cache-clean)
#+end_src

* Usage

** Menu

Run =M-x magento-cache-clean-menu= to open the transient menu.  The
Magento root is detected when the menu opens (with =C-u=, or when it
can't be detected, you are prompted for it; =M-n= offers the roots you
already have buffers for).  In the menu you can:

- Select verbosity level (silent / verbose / debug)
- Toggle =--keep-generated= and =--no-flood-guard= flags
- Pick a =--file-list= file
- Enter cache types to clean (comma-separated; any type name is accepted)
- Run a one-shot clean, start or restart watch mode, stop the watcher,
  or stop all watchers

Save defaults with =C-x s=; =M-x magento-cache-clean= and =M-x magento-cache-clean-watch= use them when called outside the menu.

** Direct commands

- =M-x magento-cache-clean= -- clean caches once
- =M-x magento-cache-clean-watch= -- start watch mode (comint)
- =M-x magento-cache-clean-watch-stop= -- stop the watcher of the current
  root; elsewhere, pick one of the running watchers
- =M-x magento-cache-clean-watch-stop-all= -- stop all running watchers
- =M-x magento-cache-clean-watch-restart= (or =M-x revert-buffer=) in a watch
  buffer -- restart it with the same arguments

From Lisp, pass cache-clean command line arguments:

#+begin_src emacs-lisp
(magento-cache-clean '("--keep-generated" "layout"))
(magento-cache-clean-watch '("--no-flood-guard"))
#+end_src

Watch processes are named after their buffer, so =M-x list-processes=
shows which root each one watches.

** Watch mode hotkeys

In the watch buffer, every printable key is sent straight to cache-clean,
which handles it as a hotkey. cache-clean prints the list of hotkeys when
the watcher starts; see the [[https://github.com/mage-os/magento-cache-clean#hotkeys][upstream README]] for details.
The output itself is read-only.

=C-c C-c= stops the watcher and =C-c C-r= (or =M-x revert-buffer=) restarts
it with the same arguments.

** Window placement

Output buffers are named after the Magento root, so they can be placed with
=display-buffer-alist=:

#+begin_src emacs-lisp
(add-to-list 'display-buffer-alist
             '("\\`\\*magento-cache-clean-watch: "
               (display-buffer-in-side-window)
               (side . bottom)
               (window-height . 0.25)))
#+end_src

** Symlinked roots

Watchers and output buffers belong to a root by its name, which isn't
resolved, since that is slow on remote hosts.  A root reached through
a symbolic link, such as both =/home/me/shop= and =/var/home/me/shop=,
gets a watcher for each name.  Set =magento-cache-clean-directory= to
one name to always use it.

** Remote watchers

Killing a watch buffer, stopping a watcher or exiting Emacs interrupts
the watcher on the remote host, since ending Tramp's local process
alone would leave it running.  This waits for the remote host to answer,
at most =magento-cache-clean-interrupt-timeout= seconds, so over a
connection that hangs instead of failing, such as SSH without
=ServerAliveInterval=, the watcher may be left running.  Set it in your
SSH configuration to make a lost connection fail quickly.

* Customization

| Variable                                  | Description                                 | Default |
|-------------------------------------------+---------------------------------------------+---------|
| =magento-cache-clean-executable=          | Which cache-clean to run (see below)        | =auto=  |
| =magento-cache-clean-directory=           | Magento root (nil = auto-detect)            | =nil=   |
| =magento-cache-clean-error-regexp-alist=  | Regexps that make one-shot output clickable | =nil=   |
| =magento-cache-clean-watch-query-on-exit= | Ask before killing a running watcher        | =nil=   |
| =magento-cache-clean-interrupt-timeout=   | Seconds to wait for a watcher to stop       | =5=     |

** Executable

With the default =auto=, the first one found of these is used:

1. =vendor/bin/cache-clean.js= in the Magento root (composer install)
2. =cache-clean= on =PATH=
3. =cache-clean.js= on =PATH=

The =.js= scripts are skipped when =node= isn't found.  If nothing is
found, the command stops with an error listing what it tried.  The menu
heading shows which executable will run.

Note that =auto= runs the project's own =vendor/bin/cache-clean.js=, so
only use it in projects whose code you trust, as you would =bin/magento=.

To force one, set =magento-cache-clean-executable= to one of those three
names, or to any program name or file name.  A relative file name with a
=/= is relative to the Magento root.  It can also be a function that
takes the Magento root and returns such a string, or nil to auto-detect:

#+begin_src emacs-lisp
(setq magento-cache-clean-executable
      (lambda (root)
        (when (string-match-p "/legacy-shop/" root)
          "~/bin/cache-clean-1.0")))
#+end_src

** Directory local variables

=magento-cache-clean-directory= is safe for use in =.dir-locals.el= when it is
an absolute directory name on the same host as the file (a relative one
would be resolved against each file's own directory, and a remote one such
as =/sudo::/= could run cache-clean as another user), and so is =magento-cache-clean-executable= when it
is =auto= or one of the three names above:

#+begin_src emacs-lisp
((nil . ((magento-cache-clean-directory . "/path/to/magento")
         (magento-cache-clean-executable . "cache-clean"))))
#+end_src

Any other executable value is not marked safe, since a =.dir-locals.el=
could otherwise run any program.  Emacs asks before applying it; answer
=!= to remember the value.

* Development

#+begin_src sh
make          # byte-compile, checkdoc, package-lint, tests
make test     # tests only
make test SELECTOR='(not (tag docker))'   # without the Docker tests
#+end_src

=make package-lint= installs package-lint from MELPA into =.deps/= first.

The tests tagged =docker= run the real cache-clean in a container
built from =test/docker/=, reached through Tramp as a remote Magento
root.  They are skipped when Docker isn't available, unless
=MAGENTO_CACHE_CLEAN_REQUIRE_DOCKER= is set, as in CI.  The image is
built on first use and rebuilt when its files change.
